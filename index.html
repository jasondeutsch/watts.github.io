Declarative agentic software workflows

A defined process for
agentic software development.

Agent sessions are difficult to assess when instructions, checks, and review vary from task to task. Watts makes those choices explicit, retains execution evidence, and gives teams a process they can evaluate and revise.

Purpose

Make the development process inspectable.

A useful result from an agent does not explain which parts of the process contributed to it. Teams need a record of configuration, decisions, and verification to diagnose failures and assess changes.

Inconsistent execution

Prompts, tools, context, and review often depend on the individual session. Versioned workflow packages establish a shared definition while allowing task-specific configuration.

Difficult failure diagnosis

A failed task can involve model output, tool execution, checks, or infrastructure. Explicit stages and retained attempt evidence help identify where work failed and what can be retried.

Unverified process changes

A new model or instruction may appear better on one task. Comparable evaluation cases connect a configuration to accepted outcomes, resource use, and human judgment.

Resource model

Configuration
through manifests.

Workflow resources define routing. Agents declare model-assisted work; Procedures declare model-free execution. ConfigMap and Secret resources supply configuration and credential references.

An Agent combines a container runtime with model configuration, instructions, tools, and completion gates.

Evaluation and accountability

Assess outcomes
against resource use.

Assess accepted work alongside reported tokens, elapsed time, known costs, and human intervention. Include failed attempts and rework so comparisons reflect the full execution.

Evaluation record What to retain
01 / DefinitionWorkflow, values, images & inputs
02 / OutcomeAcceptance, checks & review findings
03 / ResourcesReported tokens, time & known cost
04 / JudgmentSame cases. Same rubric. Human review.

Unknown usage stays unknown. Reproducible conditions do not guarantee identical model output.

Proposed managed operations

Operating workflows across a team

The proposed Watts Platform would manage orchestration, workload execution, evidence storage, and shared access. The aim is to reduce infrastructure maintenance while preserving inspectable, configurable workflow definitions.

This remains a product concept. Distributed execution, complete usage accounting, and hardened multi-tenant isolation are open work.

Project status and documentation

Current implementation

Watts currently supports local Docker workloads, Temporal orchestration, pinned execution definitions, and retained attempt evidence. The documentation describes configuration, execution, recovery, and current limitations.
